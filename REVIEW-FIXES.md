# Review fixes: palette v12

The external review covered `harmonic-grid.js` and `palette.js`; the sharing repository now includes every imported module, including `grid-auto.js`, plus the complete tests and standalone build.

`npm test` runs 139 checks. `npm run build` rebuilds both self-contained HTML files. Audio stays local. The original v12 score JSON omitted audio; v13 portable take JSON embeds its source so it can restore and render independently.

Remaining boundaries: the 2048-sample analysis is approximate for polyphonic/noisy/low-pitched signals; residual energy includes window leakage. Rank-based PCA preserves neighborhood grouping rather than exact projected distances. Changing recordings may still have loop-seam artifacts. Rate transposition is not time stretching. Take import and eight-partial harmonic preset generation were added in v13; spectral morphing remains unimplemented. Browser measurements do not establish firmware capacity.

This removes low rumble without the initial filter transient corrupting clean first-frame pitch. Correlation at the chosen lag can use the stronger raw/filtered repeat confidence; source samples and harmonic FFT amplitudes remain unfiltered. Correction: the original v13 test covered 220/25 Hz at coefficient −2/+4 dB and 330/40 Hz at coefficient −2 dB only. It did not cover +4 dB rumble at 40/45 Hz, and those coefficient levels were not equal-RMS component levels. The v14 matrix below supersedes this incomplete test.

- Grid colors, default click/drag members and similarity comparisons use each pool's middle member. Static row/random/knight patterns choose seeded members throughout the pools. Explicit member selections remain exact.
- Walk/knight generators escape isolated sites with seeded nearby-cell fallback; extinct Life reseeds a different occupied area. Dense-grid movement and Conway generation rules retain their existing tests.
- Page, keyboard and performance-step containers have labeled group roles. Headerless WebM metadata is probed with a bounded seek before payload/decode; unknown duration still times out and long duration is rejected. Native browser QA accepted a one-second WebM with no duration header and rejected its 31-second counterpart while preserving the current source.
- Grid takes now persist source PCM, score, settings and selection in IndexedDB and portable v3 JSON. Imports restore controls and exact frame/member identity, including legacy v2 scores with a matching loaded source. Replay has audio, selection-only and combined modes. Manual path writing captures pointer/arrow timing. WAV exports one score pass through fresh CAS effects, with duration/voice limits. Selected cells generate editable eight-partial harmonic presets with retained-energy reporting. See GRID-RECORDINGS.md.

Seventeen new checks pass alongside the earlier 99. ## V14: second follow-up corrections

- The cutoff is now 50 Hz. The original 40 Hz implementation reproduced the failure on the new RMS-normalized matrix: 330/40 Hz at +4 dB was correct in only 4/32 cases (25 octave-low, 3 unpitched); 440/45 Hz at +4 dB was unpitched in all 32. The new version passes 32/32 for each of five conditions: 220/25 Hz at −2/+4 dB, 330/40 Hz at −2/+4 dB, and 440/45 Hz at +4 dB. Rumble phase varies independently over eight angles, at four frame positions. Component levels are RMS-normalized over a one-second reference, with a test assertion on the dB ratio. A local raw-correlation refinement is used for highly periodic low tones to avoid reflected-filter first-frame bias. The clean matrix passes 160 sine/saw trials at ten frequencies from 62 to 3000 Hz, two phases and four positions. Stored waveform and harmonic FFT remain unfiltered.
- Fractional division option values are canonical `0.25` and `0.5`, matching restored numeric settings. Real browser store/load and JSON import restored 0.46 and 0.92 ticks/s at 110 BPM.
- IndexedDB v2 separates `takeSummaries` and `takePayloads`. Library lists and renames query only summaries; undo availability uses a key lookup. The v1 full-record migration happens once, atomically. Rename and persistent single-level delete/undo are available without clearing synth SAVE. Native browser checks inspect the accessed store names and preserve the original patch storage.
- Path disarm no longer sets the final interval from the time spent reaching the stop button. The last step repeats the preceding movement gap, or the grid clock for a singleton. STEPS/SECOND never deletes recorded intervals. SCORE TIMING explicitly selects recorded or uniform playback/rendering; the stored intervals survive switching in either direction. A browser path exported before/after clock edits, timing-mode switches and delayed disarm had identical interval arrays.
- Unsaved synth edits are guarded before take load, captured-settings application and harmonic-preset generation. The in-page Keep edits action leaves the patch and grid unchanged; Replace patch explicitly proceeds.
- Live and offline playback share GrainBudget reservations over sounding time intervals, including the same 1 ms source-stop margin. Queuing 100 ms early no longer consumes the audible budget. Tests compare admitted dense-chord events under actual lookahead batches and chronological render scheduling at four grain durations; short dense grains retain every voice. Native allocation still has a separate 96-node safety guard above bounded score scheduling needs. Native resampling, live parameter motion, unrelated previews and existing effect history can still change audio samples; those are separate from the corrected grain-admission rule.

A native dense-chord check captured 0.5 seconds of live dry output: 25 pulse packets, every interior gap exactly 20 ms. Its 12-step offline counterpart admitted 96/96 grains with zero omissions. This directly exercises the former lookahead-count failure.

The complete Node suite has 124 checks. Six additional native IndexedDB checks pass through tests/storage.html. See GRID-RECORDINGS.md for the current controls and persistence/render contract.

## Known pitch limit: mains hum

The pitch estimate is monophonic. Mains hum near the target tone's level can compete as a second periodic source; the 50 Hz analysis filter does not guarantee rejection of 50/60 Hz interference. The external review swept 50/60 Hz hum under 110–440 Hz saws, with 32 phase/frame-position combinations per condition: every case at −20 and −10 dB hum was correct; 60 Hz at −2 dB lost the intended pitch; 50 Hz at +4 dB under 440 Hz produced octave-low estimates in 13/32 cases. These are reviewer-reported results, separate from the repository's normalized sub-range-rumble regressions. Loud-hum failure remains a documented limit; this revision leaves the detector unchanged.

Browser QA recorded a three-step path with unequal intervals and edited gain/length/transpose. Exported JSON after undo of each generator, Clear, Delete step, Keep last 32 and stored-take loading matched the pre-action export exactly. A 44.1 kHz short take replaced the six-second 48 kHz source; undo recovered the full original PCM, selected pooled member, three steps, settings and synth configuration. Canceling the dirty-patch prompt on both load and undo, and importing an invalid-frame take, retained the existing checkpoint. Ordinary generator undo preserved subsequent synth edits. The recovered native WAV (0.67142 seconds, 64500 bytes) matched a fresh render from exported JSON byte for byte. No browser warning/error logs or 320-pixel horizontal overflow were observed. The module was left stopped with writing disarmed.

## V16: high-rate analysis and documentation

- Feature windows now grow with source rate while the 2048/1024 playback grid, frame count, IDs and frame-grain lengths remain fixed. Standard 88.2/96 kHz uses 4096 feature samples; 192 kHz uses 8192. An additional lag-cap check covers unusual rates near the rounding boundary. Both pitch and harmonic FFT use the larger context.
- Simply reflecting a partly observed low cycle into a centered 192 kHz window produced edge pitch bias. The implementation prefers a complete real window at file boundaries and reflects when real context is insufficient. A narrow raw-correlation refinement on highly coherent low tones in enlarged windows corrects filter-edge period bias. Existing 44.1/48 kHz paths remain unchanged: 68 generated-source before/after feature results matched exactly locally, with permanent baseline-feature regressions.
- Nine new checks bring the suite to 139: 62/80/100/150 Hz at five standard rates within 0.2%, high-rate phase/edge cases, harmonic balance, frame/grain preservation, exact 96 kHz take IDs/selection/PCM, legacy-rate feature values, short sources and a six-second 192 kHz demo. The demo improved from the review's 417/1124 pitched frames to 1122/1124 locally; the 48 kHz demo remains 279/280. This is defined coverage, not a general pitch guarantee.
- Loud mains hum remains a known competing-source limit. Multi-candidate continuity and persistent hum notches are optional future experiments; neither was added. Frame-cut grains retain sample-based duration, so they remain shorter in time at higher rates. Corrected f0 can change Period-cut behavior and feature-based layouts.
- The public README now includes the panel/keyboard/MIDI/transport/scope guide and a concise current status. The handoff starts with current behavior, limits and next checks. Curated theory, buffer, crossing and validation documents are included without dependencies on local build logs. HYBRIDIZATION.md ranks further designs and distinguishes playable existing combinations from proposed modes. The standalone instrument includes a short hybrid-recipes disclosure.

## V17: grid dynamics, ratio scales, wavesets and golden renders

- Golden SHA-256 hashes of twenty deterministic renders (all twelve algorithms, operator, effect, buffer and recall patches, and Frame/Period/Waveset grid takes) now run in `npm test`. `npm run golden:update` refreshes them after an intended change. Exact matching is required on x64; other architectures accept a tight block-RMS fingerprint because V8's math library may contract multiply-adds there.
- Two players join the eight: Kuramoto phase-coupled chords (16 cells nearest the anchor, natural rates from f0 ratios, COUPLING K) and a Chirikov standard-map walker (KICK K, stride = iterations per tick). Only these modes draw extra seeded values, so earlier players keep their sequences.
- Pitch quantization adds the odd harmonic series 1–15, 5-limit just major and the 1·3·5·7 hexany, rooted at the anchor cell's f0 (median pitched f0 for unpitched anchors).
- CELL PLAYBACK adds wavesets: rising-crossing segments repeated 1–4 times and/or every 2nd–8th dropped, then one Hann window. Live and offline share construction; duration follows the buffer.
- Take v3 settings gain optional waveset and coupling fields with backward-compatible defaults. Twenty-one new checks bring the suite to 160. See VALIDATION.md for measurements and browser QA, and HYBRIDIZATION.md for the assessment of the remaining external proposals.
